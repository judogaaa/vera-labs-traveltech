# О!Подбор — конкурсный показ (3–5 минут)

## Старт

```powershell
copy .env.example .env   # если ещё нет; токен WRITE обязателен
npm run dev:all
```

Открыть http://127.0.0.1:5173/

Мутации требуют серверный `HOTEL_INTELLIGENCE_WRITE_TOKEN` (скрипты: заголовок `X-Write-Token`) либо demo-session cookie после `POST /api/hotel-intelligence/demo/session` (только loopback + DEMO_MODE). Токен **не** кладётся в `VITE_*`. Заголовок `X-Demo-Mutation` **сам по себе** прав не даёт.

## Сценарий для жюри

### 1. Уникальный Vera Labs — поиск по фото (~45 с)
Главная → загрузить фото отеля → похожие → каталог.  
Подчеркнуть: это уже работающий продукт, «О!Подбор» — аддон.

### 2. «О!Подбор» обычными словами (~60 с)
`/hotel-intelligence` → «максимум 10 минут пешком до метро».  
Показать: совпало / неизвестно / не совпало. Тишина часто **unknown**, не «low».

### 3. Настоящее гео (~45 с)
Карточка отеля → walk: минуты, вход метро, OSM/OSRM URI, polyline на карте.  
Сказать: маршрут пешком OSRM foot, не «птичка».

### 4. Доказательства (~30 с)
Источники, статусы `estimated` / `unknown`, локальный OSM-снимок (ODbL).  
Не называть эвристику шума измерением в дБ.

### 5. Нет факта → отельер (~60 с)
Запрос «Deluxe с плотными шторами» → неизвестно / кабинет.  
Симулированный ответ: «В Deluxe blackout есть, в Standard — нет».  
Явно: **симуляция**, статус `unconfirmed`, `hotelier_simulated`, scope = номер.

### 6. Обновление поиска (~30 с)
Повторный поиск Deluxe → match с room scope.  
Противоречие → конфликт, обе версии. Перезагрузка — история на месте.

## Чего не говорить
- Симуляция отельера = реальный менеджер отеля.
- Proxy шума = замер дБ.
- GitHub Actions зелёный, пока billing блокирует jobs.
